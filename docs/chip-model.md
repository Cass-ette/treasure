# 筹码分布模型

这是从公开行情估算的成本分布，不是交易所、中登公布的持仓成本，也不是经实证确认能提高投资收益的模型。日线无法识别买卖双方的原始成本、重复换手、ETF 申赎和全部历史持仓；三角分布与均匀分布都是日内成交价格的假设。

## 数据与默认模型

东方财富日 K 接口使用 `klt=101,fqt=1`（日线、前复权），`f61` 为换手率百分数，例如 `1.5` 表示 1.5%。所有有效交易日都有换手率时，默认使用换手率递推：

```text
r[t] = min(turnover_rate[t] / 100, 1)
D[t] = (1 - r[t]) * D[t-1] + r[t] * F[t]
```

`D` 和 `F` 都是总和为 1 的价格桶概率分布。首个交易日以当日分布初始化；之后假设各成本价位等比例卖出，再加入当日新成本。换手率不再和成交量重复相乘。

- 默认 `F` 是最低价至最高价上的三角分布，峰值取 `(open+high+low+close)/4`。这不是成交均价 VWAP，也不是通过逐笔成交恢复的分布。
- 可以选择均匀分布；两种方式都用累积分布函数计算每个桶的概率，避免按桶中心采样导致总量误差。
- 一字行情全部分配到一个桶；零成交日不迁移；换手率 0 保留旧分布；超过 100% 截至 100%，并报告次数。这一截断是模型约定，不能消除重复交易的影响。
- `initial_mass_remaining = ∏(1-r[t])`（不含初始化日）。它是窗口首日假设剩余的权重，越高表示结果对未知的窗口前持仓越敏感，**不是置信度**。

只要一个有效交易日的换手率缺失、为负或非有限数，整段回退旧模型，并显示覆盖天数与原因。`model=legacy` 可主动对照旧算法：每日成交量在高低价之间均匀分配，按 `volume × decay^N` 加权。半衰期为 `log(0.5)/log(decay)`：0.97、0.985、0.995 分别约 23、46、138 个交易日。衰减参数只作用于旧模型。

## 缓存与升级

启动时对现有 `etf_kline_cache` 安全添加可空的 `turnover_rate` 列。首次查询会刷新整个缓存窗口并回填换手率，同时更新前复权历史，避免除权前后的价格基准混用。不会修改账户、持仓或交易记录。

成功的市场数据快照复用 15 分钟；扩大窗口立即刷新，失败一分钟后可重试。远端返回明显不足的历史时保留原缓存。东方财富失败且没有任何缓存时，才尝试原有 akshare 新浪 ETF 备用源；该源没有换手率，因此使用旧模型。已有缓存不会与备用源混合。备用源需要另行安装 `akshare`。

页面显示数据截至日期，行情失败时可能使用旧缓存。实时价格仍是行情快照，成本分布只更新到日 K 数据；盘中不是逐笔实时估算。东方财富成交量为手，新浪为股/份，本实现保留原始单位，不使用成交额/成交量推断价格。

## 接口与解读

`/charts/api/etf/<symbol>/chip-data` 支持 `days=1..1250`、`bins=10..240`、`model=auto|turnover|legacy`、`shape=triangular|uniform`、`0<decay<=1`、`0<band<1`。指定 turnover 但数据不完整也会明确回退。

返回 `model` 包含实际模型、分布假设、覆盖率、回退原因、初始化残留和截断次数。`distribution.weight` 保留各模型原始单位，`distribution.share` 总和为 1，用于统一百分比展示。图形平滑仅用于显示，指标基于原始桶计算。

“现价附近占比”是现价 ±band 内的概率，不是软件常见的 70%/90% 成本区间集中度。“获利盘”和“平均成本”都只是该估算分布下的指标，峰位也不保证支撑或压力有效。没有官方真实持仓成本数据作为验证基准，不能把程序测试通过解释为模型准确性或预测收益得到证明。

实现为本项目独立编写，未复制未声明许可证的社区实现；没有声称复现某个商业平台的专有算法。
