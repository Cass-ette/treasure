# 多语言支持（i18n）设计文档

**日期**：2026-08-18
**状态**：已批准，待实现
**作者**：Cass-ette

## 背景

项目所有 UI 文案硬编码中文（16 个模板 / 2162 行、6 个 JS 文件、44 处 flash 消息、约 27 处 jsonify 返回的中文消息），无任何 i18n 基础设施。用户未来可能出国、可能玩美股，需要：

1. 中英双语界面
2. 颜色习惯随语言切换（zh→红涨绿跌，en→绿涨红跌），保留手动覆盖
3. 架构留出扩展位（未来加语言只需新增翻译文件）

项目已有基础：`base.html` 的 `data-color-mode` 属性 + localStorage 持久化 + dashboard 手动切换按钮。可复用。

## 关键决策

| 维度 | 选择 | 理由 |
|---|---|---|
| 方案 | Flask-Babel 管模板+Python；渲染时 .mo 导出 JSON 注入 JS | 单一真相源；无 JS 提取器构建负担 |
| 目标语言 | 中英双语 | 需求范围；架构支持后续扩展 |
| msgid | **中文原文** | 源码可读；翻译缺失降级显示中文 |
| 默认语言 | **cookie** → Accept-Language | 用户选择持久（1 年 cookie），无 session 过期/刷新循环问题 |
| JS 文案 | 后端注入 `window.I18N`，`t('中文键')` 取值 | 不依赖 Babel JS 提取 |
| JSON API 消息 | 服务端 jsonify 前 `_()` 翻译 + `%(name)s` 参数插值 | JS 直接展示已翻译文本，无需客户端查表 |
| 颜色模式 | 跟随语言（zh→cn / en→intl）+ 手动覆盖 | 复用现有 data-color-mode |
| 切换入口 | 导航栏下拉（语言 + 颜色模式都收进来），**置于登录判断之外** | 登录页也可切换 |
| 市场适配 | **明确排除**（YAGNI） | 美股指标差异是 market 层问题，与语言正交 |
| 日期格式 | **不做**（YAGNI） | 现有 strftime ISO 格式语言中性 |
| 复数 | **不在范围** | 现有文案（"成功 X 个"）复数不变式，无需 gettext 复数机制 |

## 语言探测

```
1. cookie 'locale'           用户选过（1 年有效）→ 直接用
2. Accept-Language 头        en* → en，其余 → zh
```

**为什么用 cookie 而非 session**：session 过期后需要 localStorage→session 桥接跳转，存在刷新循环风险和错误语言闪烁；cookie 由浏览器持久化，无需桥接，天然免疫这两个问题。localStorage 不参与语言状态（只用于颜色覆盖）。

## 切换接口

```python
@bp.route('/locale/set', methods=['POST'])
def set_locale():
    lang = request.form.get('lang')
    if lang not in ('zh', 'en'):
        return jsonify(ok=False, error='invalid lang'), 400
    resp = jsonify(ok=True)
    resp.set_cookie('locale', lang, max_age=365*24*3600)
    return resp
# 前端：POST 成功后 location.reload()
```

POST 防误触/预加载。`get_locale()` 读 cookie：`request.cookies.get('locale')`，不存在时回退 Accept-Language。

## 颜色模式三态

```
跟随语言（默认）: locale=zh → data-color-mode="cn"；locale=en → "intl"
手动 cn / intl   : localStorage.colorMode 存在即视为覆盖，切语言不再联动
```

**旧值迁移**：现有 `localStorage.colorMode`（'cn'/'intl'）直接视为手动覆盖——用户确实手动点过切换按钮，语义一致，无需迁移逻辑。新用户无此键 → 跟随语言。用户选"跟随语言"时前端**删除** `localStorage.colorMode` 键退出覆盖态。base.html 的硬编码 `data-color-mode="cn"` 改为服务端按 locale 渲染初始值，前端脚本检查 localStorage 覆盖。

现有 dashboard.js 的切换按钮移除，功能收进导航栏下拉（三态：跟随语言 / 红涨绿跌 / 绿涨红跌）。

## JS 字典注入

base.html `<head>` 内、main.js 之前注入：

```html
<script>window.I18N = {{ js_translations()|tojson }};</script>
```

`js_translations()`：按当前 locale 从 Babel 缓存的 catalog 读全部 msgid → `{msgid: msgstr}`。渲染时调用，Babel 内部缓存 catalog，无性能顾虑（~百键级，几 KB）。

```js
var t = function(k){ return (window.I18N || {})[k] || k; };
t('数据加载失败')  // zh: 原样；en: 'Data loading failed'
```

要点：
- 兜底返回原中文，缺键不炸
- 动态拼接拆开：`t('现价') + ' ' + price.toFixed(3)`
- JS 键必须与 .po msgid 逐字一致；用测试抽查关键键

## JSON API 消息翻译

服务端 jsonify 构造时直接 `_()`（请求时已有 locale 上下文）：

```python
# 改造前
return jsonify({'message': f'基金 {code} 已存在于系统中'})
# 改造后（gettext 具名参数插值）
return jsonify({'message': _('基金 %(code)s 已存在于系统中', code=code)})
```

JS 端直接 `showNotification(data.message)` 展示，无需客户端查表。覆盖 image.py / funds.py / ai_assistant.py 等约 27 处。

## 翻译文件与构建

```bash
pybabel extract -F babel.cfg -o app/translations/messages.pot .

pybabel compile -d app/translations
```

## 覆盖范围

**翻**：
- 模板静态文案
- Python flash（44 处）
- Python jsonify 消息（约 27 处）
- JS 动态文案（75 行）

**不翻**：
- DB 数据（基金名/用户名/备注/OCR 内容）
- 服务端日志（保持中文，排查友好）
- AI 助手导出的 markdown 内容（`"导出时间：..."` 属生成内容，与 UI 壳无关）
- 日期格式（ISO 中性，YAGNI）

**语言与内容解耦**：切语言只换 UI 壳；美股市场适配（涨跌停/盘前盘后等）不在本次范围。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| JS 键与 .po 不一致 → 静默回退中文 | 迁移时 grep 提取 JS 中文串统一进 .po；测试抽查 |
| 忘记跑 pybabel compile → 翻译不生效 | debug 模式启动时检查 .mo 比 .po 旧则自动 compile（babel.py 内做） |
| 文案遗漏（某处还是中文） | grep 扫描模板/Python 残留中文字面量，迁移完成后跑一遍清零 |
